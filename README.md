# SayoriKujo — Саёри Кудзё

## Запуск в Windows 10/11

1. Скачайте и **распакуйте весь архив** проекта в любую папку.
2. Запустите двойным щелчком **SayoriKujo.bat**.
3. Браузер автоматически откроет локальную страницу после проверки готовности сервера.

Нужен **Python 3.10 или новее**. Проверяется Python в `runtime/python.exe`, затем `.venv/Scripts/python.exe`, затем системные `py -3`, `python` и `python3`. Дополнительные пакеты, права администратора и интернет для запуска не нужны. Python автоматически не скачивается.

Папка проекта определяется по расположению BAT. Пробелы и кириллица в путях поддерживаются; текущая рабочая папка и буква диска значения не имеют. BAT не меняет системные настройки и не устанавливает пакеты.

ОС автоматически выделяет свободный порт. Сервер резервирует его сразу, без разрыва между проверкой и запуском, и слушает только `127.0.0.1`. Адрес выводится в консоли. Если браузер не открылся, скопируйте этот адрес вручную.

Для остановки нажмите **Ctrl+C** или закройте окно консоли. Закрытие вкладки браузера сервер не останавливает. При ошибке запуска окно BAT остаётся открытым. Каждый повторный запуск создаёт отдельный экземпляр со своим свободным портом.

На главной странице доступны отдельный модуль **«Мозги · чат и память»** и история запусков.

## Мозги: чат Cloud.ru и память из разговоров

1. Запустите BAT и откройте **«Мозги · чат и память»** на главной странице.
2. В разделе **Cloud.ru** вставьте **Key Secret** и сохраните настройки. Основной адрес — `https://foundation-models.api.cloud.ru/v1`. Совместимый адрес `inference.api.cloud.ru` предназначен для ключей/подключений, использующих именно его.
3. Нажмите **«Загрузить список моделей»**, выберите текстовую chat-модель либо вставьте точный ID вручную и сохраните. Неподходящие embedding/audio/image-модели по известным признакам отключены в списке; это фильтр, а не гарантия поддержки всех моделей сервиса.
4. При необходимости проверьте **только выбранную модель** кнопкой «Проверить модель · 1 запрос». Массовых генераций и тестирования всего каталога нет.
5. Начните разговор. После ответа при включённой автопамяти отдельный запрос к модели разберёт сообщение пользователя и сохранит полезные дословные цитаты. Статус обработки виден под чатом; счётчики памяти обновляются автоматически.

Под каждым сообщением пользователя показан его собственный статус памяти: очередь, анализ, завершение или ошибка. Статус обновляется автоматически, без перехода между разделами. Кнопка **«Что сохранено»** открывает только записи с источником в этом сообщении, включая ссылки на уже существовавшие воспоминания при объединении повторов. Если устойчивых сведений нет или записи удалены, показывается пустой результат с пояснением. Ошибочный разбор можно повторить кнопкой под сообщением; это отдельный запрос к Cloud.ru.

У ответа есть кнопка **«использовано записей памяти»**, открывающая связанные текущие записи. После ручного редактирования видна их актуальная версия; это не неизменяемый снимок текста на момент ответа. Фильтр источника можно снять кнопкой **«Показать всю память»**. Устаревшие фоновые обновления больше не сбрасывают выбранный разговор, а обновление статуса анализа сохраняет позицию прокрутки при чтении старых сообщений.

Если ответ уже записан, но его доставка/чтение завершились ошибкой, интерфейс сверяет переписку и показывает сохранённый ответ. Подтверждённый успешный запрос не помечается ошибочным и не запускается заново для восстановления отображения. До выяснения результата повторная отправка того же текста в том же разговоре из этой вкладки использует прежний идентификатор запроса. Новая редакция черновика, набранная во время ожидания ответа, не стирается.

Чат и разбор памяти тарифицируются Cloud.ru: обычный новый ответ — один запрос генерации, автоанализ — ещё один. Можно выбрать отдельную модель анализа или оставить поле пустым для использования модели чата. Сохранение настроек не запускает тест генерации. Кнопка загрузки моделей получает каталог. Автопамять можно выключить; ручной разбор отдельного сообщения остаётся доступен.

### Что сохраняется и как используется

- **Краткосрочный контекст:** до 24 последних успешных сообщений в рамках бюджета 48 000 символов плюс текущее сообщение и выбранная память. Это ограничение контекста запроса, а не удаление старой переписки. Полный разговор хранится локально.
- **Долговременная память:** автоматически извлечённые цитаты пользователя, вид записи, дата, толкование модели и ссылки на исходные сообщения. Толкование показывается отдельно и не подставляется в чат вместо исходной цитаты.
- **Постоянное ядро:** вручную подтверждённые/закреплённые записи; в контекст подставляются до 12 последних активных записей ядра.
- **Архивная память:** сохранённые записи, доступные поиску и просмотру; в контекст чата автоматически не включаются.

Перед ответом подбираются до 8 подходящих долговременных записей по локальному индексу слов, а также ядро. Это начальный поиск по словам с упрощённым учётом окончаний, без эмбеддингов. К ответу сохраняются идентификаторы использованной памяти. Чат получает выбранные записи, недавние сообщения, компактную карточку текущего проекта и сводку разговора. Анализ получает текущее сообщение пользователя и ограниченный контекст для связей: известные названия проектов, до 8 записей прогресса текущего проекта и до 8 подходящих фактов. Эти данные передаются в Cloud.ru. Ответы ассистента не становятся фактами памяти автоматически.

Повторяющиеся цитаты объединяются с сохранением всех источников в одной области: общие сведения отдельно, каждый проект отдельно. Сохранённый факт означает «так сообщил пользователь», а не внешнюю проверку истинности. Возможные противоречия по определённому моделью свойству помечаются; неподтверждённые конфликтующие записи не участвуют в поиске для ответа, пока пользователь не выберет актуальную запись. Неверная классификация/пропуск факта моделью возможны — записи можно исправить, подтвердить, закрепить, архивировать или удалить.

Команда **«Забыть»** удаляет запись и блокирует повторное автоматическое добавление той же нормализованной цитаты. Её можно снова добавить вручную. При удалении разговора удаляются сообщения, задачи анализа и его автоматические воспоминания без других источников. Вручную подтверждённые записи сохраняются. Удаление разговора во время запроса не восстанавливает его поздним ответом.

### Семь автоматических функций

Все функции разбора выполняются в рамках **одного существующего запроса автоанализа**, после ответа чата. Отдельных платных циклов для проектов, профиля и сводок нет. Локальные проверки не обращаются к Cloud.ru.

1. **Определение проекта.** Назовите проект в сообщении, например: «Проект Sakura. Цель: сделать помощницу». Анализатор предлагает название, сервер проверяет, что оно действительно встречается в исходной цитате. Последующие сообщения продолжают этот проект. При упоминании нескольких известных проектов автоматическая привязка снимается; проектные сведения без однозначной связи не превращаются в общую память. Текущий проект можно уточнить селектором над чатом. Привязка и причина показаны у сообщения. Автоматическое распознавание зависит от модели и может ошибаться.
2. **Карточка прогресса.** Во вкладке «Проекты» собираются цель, решения, сделано, осталось и место остановки. У каждой записи есть кнопка «Источник». Новая цель/точка остановки заменяет предыдущую в карточке; сообщение о выполнении может закрыть конкретную предыдущую задачу того же проекта. «Сделано» — сообщение пользователя, а не проверка кода или внешнего результата. Отложенный разбор старого сообщения не возвращает устаревшую точку остановки и не меняет более новый проект чата.
3. **Явные исправления и версии.** Фразы вроде «Теперь мне нужен английский интерфейс» могут обновить прежний факт, если анализатор указал его ID, совпали вид/свойство/область и есть явный маркер исправления в цитате. Старый факт исключается из контекста, история сохраняется. Неоднозначное изменение остаётся возможным противоречием. Кнопка «История» у памяти показывает версии с датами; «Восстановить эту версию» делает её актуальной и подтверждённой вручную. Автоматическое обновление сохраняет уровень памяти. Удаление записи удаляет её снимки версий; история отдельной связанной записи серии может остаться, пока та запись существует.
4. **Профиль.** Вкладка «Профиль» собирает актуальные общие предпочтения: язык, стиль ответов и другие явно высказанные пожелания. Повторы объединяются со счётчиком источников, подтверждённые пожелания отображаются первыми. Проектные правила, архивные, спорные и заменённые записи сюда не попадают.
5. **Подбор по задаче и проекту.** Поиск использует слова запроса, текущий либо явно названный известный проект и общие предпочтения. Ядро тоже учитывает область проекта. Одинаковая цитата в двух проектах — две разные записи; исправление в одном проекте не заменяет факт другого. Для общих вопросов и «продолжай» добавляются последние подходящие предпочтения/записи проекта. Кнопка «Память проекта» открывает отдельный фильтр. Это локальный поиск по словам и приоритетам, без семантических эмбеддингов и гарантии полного воспоминания.
6. **Автопроверки поиска.** После разбора, ручного изменения, восстановления или удаления памяти автоматически проверяются до 50 последних активных неархивных записей: нашёл ли фактический поиск ожидаемый ID по контрольному вопросу и есть ли исходная цитата либо ручное подтверждение. Вкладка «Проверки памяти» показывает пропуски; проверку можно повторить локально. Вопросы предлагает сам анализатор, поэтому это проверка поиска/источников, а не независимый экзамен интеллекта, качества ответа или истинности факта. Хранятся последние 20 запусков; сбой проверки не отменяет уже сохранённый разбор и показывается отдельно.
7. **Сводка для продолжения.** Над сообщениями раскрывается «Сводка разговора · место остановки»: последний запрос, прогресс текущего проекта и важные актуальные записи. Она сохраняется автоматически, восстанавливается после перезапуска и подставляется компактно в следующий ответ. Это сводка по ссылкам на исходные данные, а не дополнительный свободный пересказ модели; удалённые воспоминания из неё пропадают. При переходе к другому проекту предыдущая проектная сводка в его контекст не подставляется. Недавние сообщения чата по-прежнему могут содержать обсуждение нескольких проектов — для отдельной переписки создайте новый разговор.

Пример для начала: «Проект Sakura. Цель: сделать помощницу. Решили: хранить данные в SQLite. Осталось: добавить поиск. Остановились: на памяти». Затем: «Сделано: добавлен поиск. Остановились: на проверках». После завершения автоанализа карточка и сводка обновятся. Само сохранение задачи не означает, что приложение будет выполнять её без вашего запроса.

### Хранение и обработка

Переписка, память, индекс, связи с источниками и очередь находятся в **`data/brain/brain.sqlite3`**. Используется встроенный SQLite Python с транзакциями и WAL; установка сервера БД или пакетов не требуется. Память не участвует в 30-дневной очистке технических сеансов и хранится до удаления пользователем. Переносите всю папку `data/` вместе с проектом при остановленном приложении, включая файлы SQLite WAL/SHM, если они остались.

При первом запуске этой версии существующая база автоматически обновляется до схемы v2. Перед изменением создаётся SQLite-копия `data/brain/backups/before-v2-<идентификатор>.sqlite3`; повторное открытие уже обновлённой базы новую копию не создаёт. Чаты, память и настройки сохраняются. Копия содержит прежнюю переписку и память, но не файл ключа. Удаление данных в работающем приложении не изменяет старые резервные копии: при необходимости удалите соответствующие файлы из `backups/` вручную. Копии не очищаются ротацией технических логов.

API-ключ хранится отдельно в `data/brain/secret.json`: в Windows — через **DPAPI текущего пользователя**, на Linux — локальный файл с правами 0600. После переноса на другую учётную запись/компьютер Windows ключ потребуется ввести снова. Веб-интерфейс получает только признак наличия ключа. Ключ не возвращается в API, не записывается в базу чатов или логи. Известный сохранённый ключ и очевидные конструкции с паролями/токенами отклоняются в сообщениях; это не универсальный детектор любых секретов.

Очередь анализа сохраняется на диск, обрабатывается одним фоновым работником каждого экземпляра с общей транзакционной выдачей задач. Одна задача не выдаётся одновременно двум экземплярам. Ожидавшие задачи продолжаются после открытия модуля. Прерванная выполнявшаяся задача через 150 секунд отмечается ошибкой и требует ручного повтора: бесконечных автоматических платных повторов нет. При смене ключа/адреса старые задания отменяются. Ошибка анализа видна в интерфейсе и не удаляет переписку.

Чат использует обычный непотоковый запрос с минимальными полями `model`, `messages`, `stream:false`, без неподдерживаемых параметров температуры/JSON-mode/tools. Тайм-аут — 75 секунд. При HTTP 400 показывается пояснение провайдера с удалённым значением сохранённого ключа. Подключение с вашим настоящим ключом нужно проверить в интерфейсе: автоматические тесты используют имитацию Cloud.ru и не расходуют пользовательскую квоту.

«Рост» в первой версии измеряется сохранёнными воспоминаниями, связями с источниками и завершёнными разборами. Веса модели не обучаются, новый код не генерируется и не исполняется. Сервер остаётся на `127.0.0.1`; изменения через API защищены проверкой Origin и случайным токеном страницы. Данные и ключ не выдаются как статические файлы.

Официальные инструкции: [Cloud.ru — быстрый старт](https://cloud.ru/docs/foundation-models/ug/topics/quickstart) и [справочник API](https://cloud.ru/docs/foundation-models/ug/topics/api-ref).

## Скорость сети и трафик в окне BAT

При запуске показывается живая строка: текущие приём **↓** и отдача **↑** в **Мбит/с**, учтённый сетевой трафик за сеанс и отдельно локальный HTTP-трафик SayoriKujo. Обновление — раз в 2 секунды. При Ctrl+C выводятся итоговые принятые, отправленные байты и их сумма. Новый запуск начинает новый сеанс с отдельной записью в истории.

**«Сеть ПК» — трафик всех программ на физических сетевых адаптерах Windows**, включая обмен в локальной сети. Это не счётчик расхода одного процесса и не максимальная скорость тарифа. Счётчики читаются через встроенный Windows API `GetIfTable2`, без спидтестов, скачиваний, установки пакетов и прав администратора. Loopback, фильтры и туннельные интерфейсы исключаются, чтобы не добавлять обмен с localhost и повторный учёт поверх VPN. Если физических адаптеров нет или статистика недоступна, выводится **«нет данных»**.

**«HTTP SayoriKujo локально» — байты запросов и ответов локального сервера**, включая HTTP-заголовки и ответы с ошибками. TCP/IP-заголовки и неподтверждённые/непрочитанные данные в этот счётчик не входят. Внешние запросы модуля «Мозги» к Cloud.ru учитываются в общей сети ПК; этот общий счётчик не выделяет расход одного процесса. Фоновый интернет-трафик самого браузера также входит в общую сеть ПК, а не в счётчик локального HTTP.

Счётчики адаптеров начинают отсчёт с момента запуска монитора, без добавления трафика, потраченного до запуска. После сброса счётчика или временной ошибки чтения отрицательные значения и скачки не добавляются; неполный учёт помечается `*`, в итогах — «учёт неполный». В перенаправленном выводе вместо живой строки сохраняются начальная информация и итоги. При принудительном закрытии окна итоговый отчёт может не появиться.

Описание источника счётчиков: [Microsoft — GetIfTable2](https://learn.microsoft.com/en-us/windows/win32/api/netioapi/nf-netioapi-getiftable2).

## Этапы запуска, логи и история

В консоли показаны пять этапов с длительностью каждого:

1. Подготовка: проверка файлов и папки данных.
2. Поиск и проверка Python.
3. Подготовка локального сервера и выделение порта.
4. Монитор сети и история.
5. Проверка готовности и передача адреса браузеру; при ошибке предлагается ручное открытие.

В конце выводится общее время этапов запуска, начиная с инициализации PowerShell-скрипта. Оно включает создание процесса Python и подготовку браузера, но не загрузку самого Windows PowerShell до выполнения скрипта. При ручном запуске `python server.py` этап проверки Python отмечается как использование уже запущенного интерпретатора.

**История:** нажмите «История сеансов» на главной странице. В таблице — начало, состояние, длительность работы, время запуска, сеть всего ПК и локальный HTTP отдельно. Этапы раскрываются под каждой записью. Кнопка «Обновить» загружает свежие данные. Просмотр в консоли без запуска сервера: `python server.py --history`.

**Файлы:** `data/sessions/<идентификатор>.json` и `data/logs/<идентификатор>.log`. Запись JSON атомарная; каждому экземпляру выделяется собственный идентификатор. Необработанные ошибки сервера и фоновых потоков записываются с трассировкой. Подготовка и ошибки поиска Python пишутся в тот же лог из PowerShell. При отказе записи на диск сервер продолжает работу с предупреждением. Логи не содержат содержимое HTTP-запросов, заголовки авторизации и тела сообщений; наружу они не отправляются и через сайт не выдаются.

**Промежуточное сохранение:** каждые 10 секунд и при завершении. После принудительного закрытия последние секунды могут отсутствовать. При следующем запуске или просмотре через `--history` сеанс без живой блокировки отмечается «Прерван без завершения». Для записей на стадии подготовки действует пауза до двух минут, чтобы параллельный запуск не принять за аварию. Длительность и трафик прерванного сеанса остаются последними сохранёнными значениями; точное время аварии не выдумывается. Активные записи других экземпляров не меняются. Отсутствующие сетевые данные отображаются как «нет данных».

**Очистка:** остаются последние 200 завершённых сеансов не старше 30 дней. Действующие сеансы не удаляются. Очистка выполняется при запуске и нормальном завершении; в PowerShell она работает и при отсутствии Python. Python-лог ротируется по 256 КиБ с двумя архивами. Папка `data/` исключена из Git. Переносите её вместе с проектом, чтобы сохранить историю; при удалении этой папки следующий запуск создаст пустую историю.

## Проверка

```console
python -m unittest discover -s tests -v
```

Ручной запуск без открытия браузера: `python server.py --no-browser`.

Тесты автоматически запускаются в GitHub Actions: Linux с Python 3.10 и Windows с Python 3.13. В Windows дополнительно устанавливается Python 3.9 только для проверки отказа от устаревшей версии.

| Сценарий | Что проверяется |
| --- | --- |
| Другой диск | BAT запускается через отдельную букву диска `subst`, рабочая папка остаётся на исходном диске |
| Сложный путь | Кириллица, пробелы, скобки, `&` и `!` в одном пути |
| Нет Python / старая версия | Понятная ошибка, ненулевой код завершения и ожидание нажатия клавиши; для старой версии используется настоящий Python 3.9 |
| Повреждённый первый Python | Нерабочий `runtime/python.exe` пропускается, запускается рабочая `.venv` |
| Неполный архив | Отдельно проверяется отсутствие `server.py` и `bootstrap/start.ps1`; ошибка называет файл |
| Нет браузера / ошибка запуска браузера | Выводится адрес для ручного открытия, сервер продолжает отвечать, повторных попыток открытия нет |
| Остановка | Настоящий Ctrl+C завершает процесс с кодом 0, порт больше не принимает соединения |
| Перенос | После остановки и перемещения всей папки проект снова запускается без изменения настроек |

Проверки BAT, Python и буквы диска выполняются в Windows; на Linux они пропускаются. Для локальной проверки устаревшей версии задайте `SAYORI_TEST_OLD_PYTHON` — полный путь к исполняемому файлу Python 3.9. Без этой переменной локально пропускается только этот сценарий, а в CI её отсутствие считается ошибкой.

Сохраняются проверки параллельных экземпляров, готовности перед открытием браузера, маршрутов страницы и отсутствия доступа к исходным файлам через HTTP. Тесты используют временные папки и не изменяют установленный Python или пользовательские файлы.

Проверки модуля памяти включают изоляцию проектов, объединение повторов внутри области, профиль, явные и неоднозначные исправления, версии и восстановление, поздний фоновый разбор, удаление источников, сводки, миграцию старой базы с резервной копией и локальные проверки поиска. Отдельный сценарий Playwright открывает настоящий Chrome: настройки, потерю ответа, статусы, фильтры источников/ответа/проекта, историю версий, профиль, прогресс, проверки, сводку после перезагрузки и мобильную ширину. Провайдер во всех этих проверках имитируется.
